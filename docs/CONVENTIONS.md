# Conventions

## General

- Language of code, comments and docs: **English**
- Branches: `feature/<NNN>-short-name`, `fix/<short-name>`
- Commits: [Conventional Commits](https://www.conventionalcommits.org/) — `feat(orders): add order creation endpoint`

## Backend (.NET 10 / C# 14)

- File-scoped namespaces, primary constructors, collection expressions, records for DTOs
- `sealed` by default for classes not designed for inheritance
- Async all the way; pass `CancellationToken` through every async call
- Endpoints return `TypedResults` (or `result.ToProblem()` on failure); group them with `MapGroup("/api/<feature>")`; declare `.Produces<T>()` / `.ProducesProblem(...)` for OpenAPI
- Use cases are services in `Application/Services/<Feature>Service.cs`; DTOs in `Application/DTOs/`
- Entities: private setters, static `Create(...)` factories, return `Result` for expected failures
- Save through `IUnitOfWork.CommitAsync`, never `DbContext.SaveChanges` directly
- Database: snake_case everywhere, generated by `UseSnakeCaseNamingConvention()` (`EFCore.NamingConventions`); set only the table name (`ToTable("users")`) in each `IEntityTypeConfiguration`; enums stored as int, append-only, never renumbered
- Migrations: PascalCase name describing the change (`InitialAuth`, `AddStores`); review the generated SQL before applying
- Error codes: `<area>.<camelCaseReason>` (`user.emailInvalid`, `auth.emailTaken`) as `const string` in `DomainErrors` (domain) or `<Area>Errors` (application); one translation per code under `errors.` in the three i18n files
- No business logic in endpoints or Infrastructure
- Secrets never in `appsettings.json` — use user-secrets locally, environment variables / vault in prod
- Test names: `Method_Scenario_ExpectedResult`

## Frontend (Angular 22)

- Design-system utilities first (`card`, `btn btn-primary`, `field`, `pill pill-success`… — ADR 0005), plain Tailwind utilities for layout; logical spacing (`ms-`, `me-`, `ps-`, `pe-`) so Arabic RTL works
- Every UI string translated in `fr.json`, `ar.json`, `en.json` (same keys, nested by feature: `store.form.name`)

- File names follow the Angular style guide: `home.ts`, `home.html` (no `.component` suffix); styles are Tailwind classes, a `.css` file only when really needed
- `inject()` instead of constructor injection
- Signals (`signal`, `computed`, `input`, `output`) for component state; RxJS for async streams, converted with `toSignal`
- New control flow (`@if`, `@for`, `@switch`) in templates
- Feature folders never import from other feature folders — share via `core/` or `shared/`
- Forms: Reactive forms (`NonNullableFormBuilder`); client validation mirrors the backend rule, but the backend is the source of truth
- Inputs showing emails, phones, codes, IBANs: `dir="ltr"` on the value only, never on the whole row
- 2-space indent, single quotes in TS

## API contract

- REST, JSON, camelCase
- Routes: plural nouns, kebab-case — `/api/purchase-orders/{id}`
- Admin routes under `/api/admin/<resource>`; lists take `page` (1-based) and `pageSize` (default 20, max 100) and return `{ items, page, pageSize, total, totalPages }`
- Audit action codes: `<target>.<action>` or `<target>.<sub>.<action>` (`user.block`, `user.role.grant`, `store.disable`)
- Errors: ProblemDetails `{ type, title, status, code }` — the client translates `code`, never shows `title` / `detail` to users
- Dates: ISO 8601 UTC
- Money: TND as decimal with 3 decimals (millimes)
- Phones: stored and returned as `+216XXXXXXXX`
